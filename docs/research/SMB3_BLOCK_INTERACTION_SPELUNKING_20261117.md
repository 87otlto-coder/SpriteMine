# SMB3 PRG1 — Block interactions, timed rewards, live tile state and P-Switch overlays

**Expedition 11 — 2026-11-17**. SMB3 **US PRG1 / Revision A** ONLY. This is **source-based research, not native validation**. Pinned Southbird disassembly commit `09b1bd81a788de8ceec664a34094e84ddb463117` inspected directly; no ROM bytes reopened, no MesenCE execution or fixture tests performed in this increment. Unverified in-game edge cases are explicitly hypotheses. Never publish game assets or ROM data in this repository.

The source links below point to the pinned disassembly. Companion: [Expedition 10 gameplay-to-SFX producer chains](SMB3_EVENT_PRODUCER_CHAINS_20261117.md), [World 1-1 decoder notes](SMB3_WORLD1_1_RECONSTRUCTION.md).

## Findings 77–90 (source inspection)

**77 — Block behavior comes from tile ID, hit direction, and a compact dispatch table.** [PRG008 `Level_ActionTiles`, range/hit masks, LATP/LATR](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L4828-L5002). `Level_DoBumpBlocks` searches tile-ID intervals with tile-type-specific hit-enable masks and an offset into `LATP_PowerUps` / `LATR_BlockResult`. Movement direction changes which tile ranges are searched; the desert-only pipeworks action is labelled unused. A tile's appearance alone does not determine its interactive behavior.

**78 — Bounce spawning is gated on available object/bump slots and ongoing bounce state.** [PRG008 special-block dispatch](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L5080-L5135). `LATP_HandleSpecialBounceTiles` refuses some hits if `Player_Bounce` is active, if object slots 6/7 and paired `Level_BlkBump` flags are occupied, or if a timer/position check on object slot 5 conflicts. Only accepted cases reach the 12-entry action-function jump table. Native experiments must distinguish collision detected vs block action accepted vs object spawned; do not infer a triggered block from a screen position alone.

**79 — A bounce block is a short-lived object sequence, not just a tile redraw.** [PRG001 bounce object](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg001.asm#L1004-L1228). On initialization `Level_BlkBump_Pos` becomes 10, and at position 10 the handler selects a spawned object via `Bouncer_PUp` (generally using object slot 5). Later updates move the bounce object according to `Bouncer_PUpVel`, decrement the counter, and restore/replace the logical block at completion. Timing depends on actual object update scheduling, not an assumed 10 milliseconds or unconditional 10 display frames.

**80 — The ten-coin block is a timer + finite reward count, with a lossy block ID.** [PRG008 `LATP_Coin`, `LATP_10Coin`](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L5192-L5309). Initialization sets `B10Coin_Count=9`, `B10Coin_Timer=200`, then enters the common coin action. When a request's merged block ID matches and the timer is active and count nonnegative, the count decrements and the result selects the coin-bearing brick restore code. The source's intended normal path permits ten rewards including the first; real timing/hit acceptance remains unobserved. `B10Coin_ID = XLow | XHigh` is an 8-bit **OR-folded identifier**, not a unique 16-bit coordinate. Two different locations can have an identical ID; whether any actual SMB3 PRG1 level exploits or suffers from that collision is **unverified**. `B10Coin_Timer` resides in the eight-byte `Event_Countdown[0..7]` range whose nonzero values are decremented by the [player-update tail](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L360-L389).

**81 — Tile-change requests use one shared event slot, not a FIFO.** [PRG008 `Level_QueueChangeBlock`](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L6815-L6847) writes `Level_ChgTileEvent` and one set of 16-pixel-aligned `Level_BlockChgX/Y` coordinates; [PRG029 `BlockChange_Do`](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg029.asm#L2395-L2632) consumes the current event and clears it. Some producers check the slot first; others write directly. Multiple producers before a consume can therefore overwrite each other **in principle**. An actual lost tile mutation is NOT established.

**82 — Logical level tile update and visible PPU update are distinct operations.** [PRG029 one-tile handler](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg029.asm#L2541-L2634) writes a logical 16x16 tile ID into tile RAM, then stages four 8x8 pattern IDs and a VRAM address into `TileChng_Pats`/`TileChng_VRAM_*`. The [PRG026 `TileChng_VRAMCommit`](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg026.asm#L3520-L3557) subsequently commits two top and two bottom pattern bytes through $2006/$2007 and clears the pending flag. Crucially, change events `$01` (delete coin) and `$02` (delete to background) stage **identical four visual pattern IDs** but write **different logical tile IDs** (`TILEA_COINREMOVED` vs `TILE1_SKY`). Hence identical screenshots do not imply identical collision/reload state.

**83 — P-Switch uses both a graphical CHR-bank override and virtual tile substitution.** [PRG008 P-Switch hit](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L4748-L4782) queues press animation, vibration, boom, special music and a `$80` countdown. [PRG030 CHR selection](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg030.asm#L2238-L2269) forces `PatTable_BankSel+1=$3E` while active. Separately, [PRG000 `PSwitch_SubstTileAndAttr`](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg000.asm#L1591-L1623) substitutes tile identity **on read** (coin→brick, brick→coin, muncher→coin, special P-switch coin→coin), plus collision attribute values. [PRG008 player tile reads](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L4322-L4369), [PRG007 projectile reads](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg007.asm), and [PRG000 object tile reads](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg000.asm#L1575-L1588) call the substitution logic. Therefore replay must distinguish: stored tile ID, effective collision tile, and rendered CHR pixels. Do not interpret the CHR override as rewriting the entire stored tile map.

**84 — P-Switch countdown uses a divided update clock and coordinates music.** [PRG008 update tail](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L390-L419) only decrements a nonterminal `Level_PSwitchCnt` when `Counter_1 & 3 == 0`; at count 1 it queues the appropriate restore music and decrements. The $80 initial value therefore represents many more *update passes* than 128. Under uninterrupted once-per-frame calls it is approximately 500 frames, but **exact duration in display frames is not established**. The active switch also gates some conveyor behavior ([PRG008](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L6333-L6350), [PRG000](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg000.asm#L836-L860)); P-Switch is broader than a palette/CHR effect.

**85 — Hidden 1-Up collection and ordinary coin collection participate in level regeneration.** [PRG008 `LATP_1up`](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L5310-L5318) calls `Level_RecordBlockHit` before selecting the life mushroom object. [PRG008 touching a coin](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L4724-L4742) queues delete/records the hit. [PRG014](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg014.asm#L1119-L1216) checks the bitmap while rebuilding layout commands. This does **not** make every ordinary tile change persistent; only evidenced consumers/writers qualify.

**86 — Coins above blocks have a special coupled pickup path.** [PRG008 `LATP_GetCoinAboveBlock`](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L5405-L5437) checks the 16x16 tile directly above a struck brick. If it is a coin, it queues a tile deletion and invokes the common coin-award logic. This couples a block hit to an adjacent collectible and introduces a useful test for queue overwrite/visual-vs-logical state. Actual render timing remains pending.

**87 — Some block contents depend on Player state rather than ROM tile label alone.** [PRG008 `LATP_Flower`, `LATP_Leaf`, `LATP_CoinStar`](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L5151-L5230): normal flower/leaf blocks select a mushroom for small Player but flower/leaf for a powered-up Player; Coin/Star behavior selects a star when the Player is star-invincible, otherwise delegates to the coin routine. Source tile metadata identifies a conditional **producer rule**, not necessarily the object that will spawn.

**88 — Per-hit block outcomes depend on direction and Player suit.** [PRG008 `LATP_Brick`](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg008.asm#L5231-L5285) smashes a standard brick for the tail-attack tile-detect slot or when Player is not small; otherwise the small-Player path selects a non-object result/bounce. The smash path queues a Level 2 crumble sound, seeds brick-fragment animation state and score, and requests a background tile replacement. Preserve independent physical sound, logical tile, particle/fragment and score evidence.

## Further scheduling and probe findings (89–90)

**89 — Logical tile processing and PPU commitment occur in separate execution contexts.** [PRG030 gameplay update](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg030.asm#L2495-L2507) maps PRG29 and calls `BlockChange_Do`, while [PRG031 NMI](https://github.com/captainsouthbird/smb3/blob/09b1bd81a788de8ceec664a34094e84ddb463117/PRG/prg031.asm#L1533-L1562) invokes `TileChng_VRAMCommit` in the normal video-update path, also in vertical and 32-pixel-partition paths. Thus a tile collision and logical change can be separated from the visible commit by an NMI scheduling boundary. The **exact number of observed display frames of latency is not proven**, because NMI/event phase and the `VBlank_Tick` branch matter. Instrument both routine executions with mapped PC and master clock, not just consecutive screenshots.

## Highest-value native experiments

1. **P-Switch A/B/A:** capture unchanged tile-map RAM, effective tile returned by player/object collision queries, `PatTable_BankSel+1`, mapper/CHR mapping, four consecutive scene frames, and music/counter transitions. Verify separate data/visual mechanisms and switch expiry.
2. **Ten-coin block:** log its ID, timer/count before and after each hit; record both the initial setup and the tenth reward. Try two different blocks with the same OR-folded ID **only if such positions can be reached naturally**, without modifying ROM or memory. Treat collision as a test hypothesis, not a known bug.
3. **Slot exhaustion:** reproducibly occupy object slots 5–7 and compare hit detection vs accepted block action. Avoid claims about normally reachable states until reproduced.
4. **One-tile vs one-frame timing:** log `Level_QueueChangeBlock` producer PC and coordinates, `BlockChange_Do` logical tile write, staged `TileChng_VRAM_*` and `TileChng_VRAMCommit` PPU writes. Test $01 coin deletion versus $02 background deletion with identical visual patterns but different tile identities.
5. **Coin above block:** hit a brick with an adjacent coin; trace both the coupled coin award and pending tile change. Include control without the adjacent coin.
6. **Branch-driven object spawn:** compare small and powered Player hitting the same flower/leaf block and coin/star block with and without star invincibility. Distinguish animation object ID, actual visible sprite, sound queue and map tile.

Capture provenance: immutable ROM SHA-256, emulator binary/version hash, save state hash, input plan, real frame+cycle IDs, mapped PRG PC, RAM before/after, CHR bank mapping, and actual PPU/APU output. Never export guessed frames as original or conflate source derivations with runtime verification.

## Engineering implication

SMB3 level reconstruction must support three separate states: **ROM-authored level instructions**, **live logical tile/object state**, and **PPU-visible output**. A fourth **effective collision tile** is computed by transient conditions such as P-Switch. The same background pixels can correspond to different logical tiles, and the same original tile can produce different rewards depending on runtime Player state. Build stateful per-frame traceability before claiming complete World 1-1 or general SMB3 level accuracy.
